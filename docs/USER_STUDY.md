# EduAgent — User Study Protocol

## Overview

This document provides a structured protocol for evaluating EduAgent with real students. Even a small study (5–10 participants) significantly strengthens the capstone evaluation by providing empirical evidence of the platform's effectiveness.

---

## Study Design

### Participants
- **Target**: 5–10 engineering students from your batch (or juniors studying the same subjects)
- **Prerequisite**: Enrolled in at least one of: MSA, HCI, Cyber Security, or ML
- **Duration**: 20–30 minutes per participant

### Protocol

| Step | Duration | Activity |
|------|----------|----------|
| 1 | 2 min | Briefing + consent |
| 2 | 3 min | Account creation and onboarding |
| 3 | 15 min | Guided tasks (see Task Sheet below) |
| 4 | 5 min | Post-study questionnaire |
| 5 | 5 min | Optional open-ended interview |

---

## Task Sheet (Give to Each Participant)

### Task 1: Concept Q&A (3 min)
> Pick any subject you're studying. Ask EduAgent to explain a concept you find difficult. Follow up with at least one clarification question.

**What to observe**: Does the agent adapt depth? Does it reference course material?

### Task 2: Practice Questions (3 min)
> Ask EduAgent to generate practice questions for an upcoming exam topic. Answer at least one question.

**What to observe**: Are questions relevant? Does the system evaluate the answer?

### Task 3: Weak Point Analysis (2 min)
> Ask "What are my weak areas?" or "What should I study next?"

**What to observe**: Does it identify real weak concepts? Are suggestions actionable?

### Task 4: Teach-Back / Protégé Mode (4 min)
> Type "Let me teach you about [concept]" and try explaining a concept to the AI. When finished, say "how did I do?"

**What to observe**: Does the AI ask probing questions? Is the evaluation fair?

### Task 5: Dashboard Review (3 min)
> Navigate to the Dashboard. Review your mastery heatmap, exam readiness score, and concept graph.

**What to observe**: Is the data understandable? Do visualisations help?

## System Usability Scale (SUS) — Optional

The standard 10-item SUS questionnaire for a formal usability score (out of 100):

| # | Statement | 1 | 2 | 3 | 4 | 5 |
|---|-----------|---|---|---|---|---|
| 1 | I think I would like to use this system frequently | ☐ | ☐ | ☐ | ☐ | ☐ |
| 2 | I found the system unnecessarily complex | ☐ | ☐ | ☐ | ☐ | ☐ |
| 3 | I thought the system was easy to use | ☐ | ☐ | ☐ | ☐ | ☐ |
| 4 | I would need technical support to use this system | ☐ | ☐ | ☐ | ☐ | ☐ |
| 5 | I found the various functions well integrated | ☐ | ☐ | ☐ | ☐ | ☐ |
| 6 | I thought there was too much inconsistency | ☐ | ☐ | ☐ | ☐ | ☐ |
| 7 | Most people would learn to use this quickly | ☐ | ☐ | ☐ | ☐ | ☐ |
| 8 | I found the system very cumbersome to use | ☐ | ☐ | ☐ | ☐ | ☐ |
| 9 | I felt very confident using the system | ☐ | ☐ | ☐ | ☐ | ☐ |
| 10 | I needed to learn a lot before I could use this | ☐ | ☐ | ☐ | ☐ | ☐ |

**SUS Scoring**: For odd items, subtract 1 from the score. For even items, subtract the score from 5. Sum all values and multiply by 2.5. Score > 68 = above average usability.

## Analysis Guide

### Quantitative Metrics to Report

1. **Mean scores** for each section (A, B, C, D, E) — report with standard deviation
2. **SUS score** — compare against industry benchmark (68 = average)
3. **Per-agent usefulness ranking** — which agents scored highest on D1–D4
4. **Comparison advantage** — E1–E3 mean scores show value over alternatives

### How to Present in the IEEE Paper

In your paper's **Section IX: Evaluation**, report:

```
Table VIII: User Study Results (N=X participants)

| Category              | Mean Score (σ) |
|-----------------------|----------------|
| Usability (A1-A5)     | X.XX (±X.XX)   |
| Effectiveness (B1-B6) | X.XX (±X.XX)   |
| Visualisation (C1-C3) | X.XX (±X.XX)   |
| Agent Quality (D1-D4) | X.XX (±X.XX)   |
| vs. Alternatives (E1-E3)| X.XX (±X.XX) |
| SUS Score             | XX.X           |
```

### Key Quotes
Pick 2–3 strong quotes from open-ended responses for your paper:
> "EduAgent helped me identify gaps I didn't know I had" — P3

## Ethical Considerations

- **Informed consent**: Brief each participant that their responses are anonymous and used for academic evaluation only
- **No personally identifiable information**: Use participant codes (P1, P2, ...)
- **Voluntary participation**: Participants can withdraw at any time
- **Data storage**: Keep raw data locally only, do not upload to public repositories
